## 二、 核心挑戰：圖文分離與連續發送問題

在 LINE 使用習慣中，發送者通常會採用以下順序：
1. **先發文字，緊接著發 1~2 張圖**（例如：曉光老師先說明 1~5 點，接著發施打流程圖與衛教圖）。
2. **先發檔案 (PDF)，緊接著發補充說明**（例如：黃怡瑜老師先傳 PDF，接著 @All 提醒下午會公告）。

### 解決策略：關聯訊息群組化 (Grouped Messages)
- **時間視窗判定**：同一個發送者在 **2 分鐘** 內連續發送的多則訊息（文字 + 圖片 + 檔案），自動給予相同的 `Session ID / 群組關聯碼`。
- **整合彙報**：在產生 12:00 或 16:00 整理時，將同一個群組關聯碼的文字、多張圖片與 PDF 附件合併為一個獨立的「通知主題項目」，避免信件中同一件事被切成 3 塊。

## 三、 Google Sheets 欄位規格設計

建議在 Google 試算表建立兩個工作表（Sheet）：

### 工作表 1：`Raw_Messages`（原始接收日誌）
記錄 LINE Webhook 接收到的每一筆原始訊息，作為審計日誌與除錯依據。

| 欄位英文字 | 欄位中文名稱 | 資料型態 | 說明 / 範例 |
| :--- | :--- | :--- | :--- |
| `message_id` | 訊息識別碼 | 字串 | LINE 給予的唯一 ID（如 `msg_178239123`） |
| `timestamp` | 接收時間 | 日期時間 | 格式：`YYYY-MM-DD HH:mm:ss`（如 `2026-11-04 11:24:00`） |
| `sender_name` | 發送者姓名 | 字串 | 如「曉光老師」、「黃怡瑜 Lia」、「人事室」 |
| `message_type` | 訊息型態 | 列舉 | `text` / `image` / `file` |
| `content` | 原始文字內容 | 長文字 | 若為圖片/檔案則為檔名或留空 |
| `drive_file_id` | 雲端檔案代碼 | 字串 | 儲存於 Google Drive 後取得的 File ID |
| `drive_view_url` | 檔案檢視連結 | 網址 | Google Drive 預覽/下載公開檢視連結 |
| `session_group_id`| 關聯群組碼 | 字串 | 關聯 2 分鐘內同發布者的組合代碼 |
| `is_processed` | 是否已彙整寄出 | 布林值 | `TRUE` / `FALSE` |
| `batch_tag` | 寄送批次標籤 | 字串 | 如 `20261104_1200` 或 `20261104_1600` |

---

### 工作表 2：`Digest_Summaries`（半日彙整記錄表）
記錄每日 12:00 與 16:00 經由規則整理或 AI 摘要後的正式通知條目，供查閱歷史紀錄。

| 欄位英文字 | 欄位中文名稱 | 說明 / 範例 |
| :--- | :--- | :--- |
| `digest_id` | 彙整流水號 | 如 `DIGEST-20261104-1200` |
| `send_time` | 發送時間 | `2026-11-04 12:00:00` |
| `category` | 類別標籤 | `【教務/考試】`、`【學務/活動】`、`【人事公告】`、`【榮譽榜】`、`【緊急更正】` |
| `topic_title` | 公告標題/主旨 | 例如：「下週一(11/09)全校流感疫苗施打流程與注意事項」 |
| `summary_body` | 內文條列整理 | 精簡摘要，含重要時程、地點、配合班級與任課教師 |
| `attachment_links`| 附件清單 (JSON) | 包含的圖片 URL、PDF 下載連結 |
| `recipient_count` | 寄送成功教師數 | 例如：45 位老師 |
| `email_subject` | 寄發信件主旨 | 【竹林召集人半日通報】2026/11/04 中午 12:00 重點彙整 |

## 四、 雲端硬碟（Google Drive）目錄儲存規劃

所有圖片與 PDF 附件均由 Bot 自動下載，並依照日期層級結構儲存於學校共享雲端硬碟：

```text
📁 學校召集人通知附件庫/
└── 📁 2026-11/
    ├── 📁 2026-11-04/
    │   ├── [112400] 筱惠_調移時段圖卡.jpg
    │   ├── [134600] 曉光老師_疫苗施打流程表.jpg
    │   ├── [134601] 曉光老師_流感衛教說明.jpg
    │   └── [145100] 黃怡瑜_115-1第二次段考範圍通知.pdf
```
*命名規則：`[HHmmss] 發布者_原始檔名.副檔名`，方便日後人工查閱或歸檔。*

## 六、 「召集人專用事項」vs「全校通報事項」判別準則

| 判斷面向 | 需納入 12:00/16:00 派報 (公告給全體老師) | 排除於派報外 (僅限召集人內部事項) |
| :--- | :--- | :--- |
| **語意特徵** | • 「請召集人協助傳達給各科老師...」<br>• 「請各科老師確實檢查附件...」<br>• 全校性活動日程、調課時段、疫苗施打、退休金提撥<br>• 學生得獎競賽賀報、段考範圍公文 | • 「請各科召集人明天中午至教務處領題」<br>• 「請召集人填寫審題進度表」<br>• 召集人會議出席調查、便當統計<br>• 召集人間的個別私訊對話或閒聊 |
| **建議群組標籤<br>(選用)** | 📢 **【全校轉達】**、**【各科公告】**、**【行政通知】** | 🔒 **【僅召集人】**、**【召集人內部】**、**【幹部填報】** |
| **處理機制** | Gemini API 判定受眾為全體教師，萃取時程地點條列摘要，夾帶附件寄出。 | Gemini API 判定受眾僅為召集人，自動標記 `SKIPPED`，不打擾全體老師。 |
